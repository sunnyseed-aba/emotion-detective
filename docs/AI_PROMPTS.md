## 一、最重要的前提：執行期不呼叫任何 AI

接手前請先確認一件事，因為它會影響你對整個專案的判斷：**這個專案在執行期（runtime）完全不呼叫任何 AI 模型或外部 API**。

所有 AI 的使用都發生在**開發期**，用途只有一個——生成場景與角色的圖片素材。生成完成後圖片即成為靜態資產，遊戲本身是純前端、純資料驅動的應用程式。這意味著：

| 項目 | 狀態 |
| --- | --- |
| LLM 呼叫（執行期） | 無 |
| 後端 API 端點 | 無 |
| 資料庫 | 無 |
| 使用者驗證 | 無 |
| 必要環境變數 | 無（`.env` 可為空） |
| 網路請求 | 僅載入 Google Fonts 與靜態圖片 |

`server/index.ts` 是 Manus 樣板遺留的佔位檔案，static 專案不使用它。`package.json` 中的 `express` 依賴同樣來自樣板，未被實際引用。

因此本文件沒有 System Prompt、沒有 JSON Schema、沒有 AI Workflow 可以整理——那些都不存在。本文件真正的內容是**影像生成的 Prompt 規範**，這對接手者有實質價值：未來要新增案件時，必須依照同一套規範生成素材，否則畫風會不一致。

## 二、影像生成工具

所有素材由 Manus 平台內建的影像生成模型產出。若接手環境沒有該工具，可改用任何具備同等能力的影像生成模型（如 DALL·E 3、Imagen、Midjourney、Stable Diffusion 等），但必須嚴格遵守下列規範，否則新素材會與現有七件案子的畫風脫節。

素材的完整清單、對應用途與原始檔位置記錄在 `assets/ASSET_MANIFEST.md`。原始未壓縮圖檔保存在 `assets/source/originals/`。

## 三、人物 Prompt 規範

人物繪製的核心約束是**半擬真而非卡通**。這不是美學偏好，而是教學需求：孩子必須從圖像中讀出真實可辨識的臉部肌肉動作，卡通化的符號式表情（淚滴、青筋、汗滴）會讓孩子學到符號辨識而非真實臉部解讀，無法類化到現實生活。

必須包含的要求：

- 寫實人體比例、寫實臉部解剖結構
- 眼睛正常大小、正常頭身比
- 表情依 **FACS（Facial Action Coding System）真實臉部肌肉動作** 繪製
- 柔和繪畫質感（soft digital painting），避免恐怖谷與注視壓力
- 全身、雙腳可見，方便舞台定位
- 純白或純綠背景，人物不接觸畫框邊緣（便於乾淨去背）

必須明確排除的要求：卡通、動漫、Q 版、大眼放大、誇張變形、符號式表情（不畫淚滴、不畫爆青筋、不畫汗滴）。

### FACS 表情對照表

撰寫 Prompt 時，請直接把對應情緒的肌肉動作描述寫進去，不要只寫情緒名稱。

| 情緒 | 真實肌肉動作描述 |
| --- | --- |
| 傷心 | 內側眉毛上揚並靠近、上眼瞼下垂、嘴角下拉、下巴微低 |
| 生氣 | 眉毛下壓並靠近、眼瞼緊繃、上下唇緊壓成線、下巴前推 |
| 害怕 | 眉毛上揚並靠近、上眼瞼大幅上抬露出眼白、嘴角水平後拉 |
| 尷尬 | 視線迴避向側下、單邊嘴角內收、雙頰泛紅、肩膀內縮 |
| 開心 | 嘴角上揚並向外、眼輪匝肌收縮產生眼角細紋（真笑） |
| 驕傲 | 下巴微抬、輕微閉唇笑、胸口挺起、肩膀後展 |
| 驚訝 | 眉毛整體上揚、上眼瞼上抬、下顎放鬆成小圓口 |
| 孤單 | 視線下垂、表情低張力、身體朝內收、與他人有明顯距離 |

### 姿態必須符合案情

這是踩過坑才學到的教訓。早期版本要求「全身正面站姿、雙手自然垂放」，結果所有角色都像證件照一樣站著，完全無法呈現案情動作，使用者直接指出「人物在場景中但沒有任何動作」。

現行規範是**每個角色的姿態必須直接對應該案的敘述**。實際採用的姿態例如：低頭壓著考卷坐在課桌椅、蹲在積木旁、伸手要拿平板、捏著衣角重心後仰不敢前進、低著頭往旁邊走開。

### 雙人同框圖

當一件案子需要兩個人同時在畫面中，且其中一位是成人，**必須在同一張圖內畫出兩人**，不可分別生成後各自縮放。原因是每張圖檔內的人物身高佔比不同，而舞台以圖檔高度套用縮放比例，分別生成必然導致比例失真（實際發生過成人過大、兒童過小的「小人國」問題）。

目前 HOM-02（小美＋媽媽）與 COM-02（阿嬤＋小宇）採用此做法。Prompt 中需明確要求兩人面對面互動、身高比例符合年齡差。

## 四、場景 Prompt 規範

場景設計的關鍵是**刻意去雜訊**。一般的插畫追求豐富細節，但對自閉症兒童而言，每一個非必要的視覺元素都是干擾源，也可能誤導他們把注意力放在無關線索上。

必須包含的要求：

- 物件比例、透視、材質皆寫實，不用扁平剪影
- 僅保留敘事必要物件，無圖案、無裝飾、無雜物
- 低對比、柔和散射光、無強烈陰影、淺景深模糊
- **人物必須是畫面中對比最高的元素**，自然引導視覺注意臉部
- 中央下方保留空白區供角色定位，避免與家具重疊
- 16:9 比例（舞台固定為 `aspect-[16/9]`）

### 案情關鍵物件必須可見

這同樣是使用者回饋帶來的修正。早期場景只有「地點」而沒有「案情」，導致所有資訊都靠文字承載，使用者指出「場景沒有畫面，只有地點加主要人物，都集中在文字說明」。

現行規範要求每個場景背景**必須包含該案的關鍵物件**，這些物件同時作為畫面上的可點擊熱點。實際案例：考卷、足球、三角錐、積木箱、平板、牆上時鐘、籃球、公園長椅、背包、落葉、水杯。

另有一種特殊需求是「旁人的存在」。COM-01（尷尬）的教學重點在於「有人看到了」，若畫面中沒有旁觀者，孩子無從推理。因此該場景的 Prompt 明確要求左後方有兩位轉頭看過來的人。

## 五、去背處理流程

生成的人物圖需要去背成透明 PNG 才能疊在場景上。相關腳本保存在 `assets/source/scripts/`，這四支腳本記錄了處理策略的演進，接手時建議直接使用最新版本。

| 腳本 | 用途與演進 |
| --- | --- |
| `cutout.py` | 首版 flood-fill 去背，處理白底 |
| `cutout2.py` | 綠幕修補與殘留光暈清除 |
| `dechroma.py` | 綠幕去色，用於 v2 世代素材 |
| `cutout_v4.py` | **目前建議使用**。保守策略：只移除外部連通的白色區域，不使用大容差全域鍵值 |

`cutout_v4.py` 的保守策略是為了修正一個實際發生的錯誤：早期使用大容差全域去背，把角色的黑色頭髮誤刪成透明破洞，使用者直接反映「小美在操場的頭髮沒有顏色」。保守的外部連通策略能保留頭髮與淺色衣服。

處理流程為：生成（白底）→ `cutout_v4.py` 去背 → 檢視棋盤格對照確認無破洞 → 縮放至網頁尺寸 → 上傳取得穩定 URL。人物圖的原始高度統一為 1400px。

## 六、素材命名慣例

檔名採 `{世代}-{類型}-{對象}-{案件}` 格式，世代編號代表重製輪次。

| 前綴 | 說明 |
| --- | --- |
| `v1-` | 紙劇場風格，已作廢不再使用 |
| `v2-` | 首版半擬真素材，場景封面仍在使用 |
| `v3-` | 加入動作姿態與案件專屬背景 |
| `v4-` | 修正比例、頭髮透明與姿態不符問題，含雙人同框圖 |
| `_web` | 已縮放為網頁尺寸的版本，程式實際引用這一版 |

`assets/ASSET_MANIFEST.md` 完整記錄每個檔案的遠端檔名、本地路徑與用途，包含已生成但未採用的素材及其未採用原因。
