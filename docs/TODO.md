## P0 — 建議優先處理

### 1. 補上正向情緒案件（開心、驕傲、驚訝）

八種情緒已完整定義在 `client/src/game/emotions.ts`，但其中開心、驕傲、驚訝三種只作為干擾選項出現，沒有任何一件案子以它們為目標情緒。目前七件案子全部偏重負向情緒（傷心、生氣、害怕、尷尬、孤單），這在教學覆蓋上是明顯缺口——正向情緒的心智推理同樣重要，例如理解「別人為什麼替我開心」或「他以為自己會得獎所以很驕傲」。

曾討論的候選情境為生日派會、比賽得獎、醫院診所。新增案件只需編輯資料檔，作業流程見 `docs/GAME_DESIGN.md` 第九節，素材規範見 `docs/AI_PROMPTS.md`。

### 2. 觀察階段缺少線索進度指示

必查線索（`essential: true`）必須全部翻開才能推進下一階段，但介面沒有告訴孩子「已看幾個、還缺幾個」。孩子可能因為不知道還缺什麼而卡住。使用者已明確提出此需求。

建議在線索區加上勾選標記或 `3 / 4` 之類的計數。引擎已有 `openedClues` 狀態可直接使用。

### 3. 結案報告缺少階段回顧

`attempts` 已逐階段記錄嘗試次數，但結案報告只顯示總分與鼓勵語，沒有呈現「哪一步最快答對、哪一步試了比較多次」。這項資訊對家長與治療師判斷孩子的弱項很有價值，資料已存在，只缺呈現層。使用者已提出此需求。

## P1 — 有價值的功能擴充

### 4. 治療師／督導模式

`GameMode` 型別已定義 `child`、`therapist`、`parent`、`teacher` 四種，但只有 `child` 有介面。`localStorage` 中的 `emotionStats`（各情緒答對／答錯統計）與 `stageStats`（各階段統計）目前**只寫入、從未讀出**，就是為此模式預留的。

實作時只需新增一個路由與展示元件，讀取既有進度資料即可，不需改動引擎。

### 5. 同一角色的「中性／情緒後」對照圖

目前每案只有一張情緒姿態圖。若為同一角色補上中性表情圖，命名階段就能前後對照，強化「表情發生了什麼變化」的辨識訓練。成本是每案多一張素材。

### 6. 真實照片素材（C 方案）

`Case.spriteReal` 與 `GameScene.backdropReal` 欄位已預留但無素材。這是使用者當初表示「未來再思考」的 C 方案，對類化到現實生活的效果最強，但涉及肖像權與感官敏感考量，需謹慎評估。切換方式已預留，補圖即可用。

### 7. 音效（需謹慎設計）

`assets/audio/` 為空是刻意決策（見 `docs/DECISIONS.md` 第二節）。若要加入，必須：預設關閉、可個別開啟、答錯絕不出聲、提供音量控制。

## P2 — 技術整理

### 8. 各案 strategyChoices 未引用共用策略庫

`client/src/game/strategies.ts` 定義了八條共用策略（含分類與文案），但各案的 `strategyChoices` 是**各自手寫**的，沒有在程式層引用此庫。這造成文案可能不一致，也讓策略庫的維護價值被削弱。

建議改為以 `strategyId` 引用共用庫，各案只覆寫案件專屬的 `feedback`。這是唯一違反「內容與引擎分離」原則的地方。

### 9. 已安裝但未使用的依賴

以下套件來自 Manus 樣板，專案未實際使用，可考慮移除以縮小安裝體積：`framer-motion`（動畫全用 CSS）、`recharts`（無圖表）、`react-hook-form`、`zod`（無表單驗證）、`axios`（無網路請求）、`express`（無後端）、`embla-carousel`。

移除前請先確認 `client/src/components/ui/` 下的 shadcn 元件是否有間接引用（例如 `chart.tsx` 依賴 recharts、`carousel.tsx` 依賴 embla）。若不打算使用那些 UI 元件，可連同元件檔一併移除。

### 10. 平台相依項目需清理

`client/index.html` 底部有 Manus 平台的分析 script，`client/public/__manus__/` 目錄含平台除錯收集器。移出 Manus 平台部署時應移除這些。

`server/index.ts` 與 `shared/const.ts` 是樣板佔位檔案，static 專案不使用，可刪除。

### 11. 未被引用的早期素材

`assets/icons/` 中有三個 v1 紙劇場風格的 icon 未被任何程式碼引用（該視覺方向已作廢）。保留作為歷史紀錄，可安全刪除。

### 12. 圖片目前指向遠端 URL

程式中的圖片路徑是 `/manus-storage/...` 遠端 URL。專案已提供 `scripts/use-local-assets.mjs` 可批次切換為本地 `assets/` 路徑，接手到其他平台部署時需執行此腳本。用法見 `README.md`。

## P3 — 長期構想

### 13. 動態難度調整

依歷史表現調整干擾選項的語意距離。目前難度為固定設計（三個層次的錯誤信念類型），無自適應機制。

### 14. 內容編輯介面

目前新增案件需編輯 TypeScript 檔案。若要讓臨床人員完全自主擴充內容，需要一個表單式編輯器輸出符合 `Case` 型別的資料。這會是讓專案規模化的關鍵，但工程量不小。

### 15. 跨裝置進度同步

目前僅 localStorage。若要同步，必須先處理兒童敏感資料的知情同意與資料治理，不建議直接接上資料庫（見 `docs/DECISIONS.md` 第九節）。

## 已知問題（Bug）

目前沒有已知的功能性錯誤。TypeScript 型別檢查通過、無 LSP 錯誤、無建置錯誤。

以下屬於品質層面的觀察，非功能性錯誤：

| 項目 | 說明 |
| --- | --- |
| 熱點座標為手工校準 | `StageProp` 的 `x` / `y` 是目視對齊背景圖物件的百分比值。若更換背景圖，必須重新校準，沒有自動對位機制 |
| 角色定位同為手工校準 | `placement.x` / `y` / `scale` 亦為目視調整，更換素材需重校 |
| 部分素材有殘留邊緣雜點 | 保守去背策略的代價，肉眼在深色背景上可能察覺 |
| 無自動化測試 | 專案無單元測試或 E2E 測試，所有驗證皆為視覺截圖檢查 |
